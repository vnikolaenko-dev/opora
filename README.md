# Опора

Личное пространство для целей, привычек, заметок с голосовым вводом, трудностей и планирования. Статическое приложение с настраиваемыми дашбордами.

## Локальный запуск

Откройте `index.html` в браузере или используйте локальный HTTP-сервер. Для голосового ввода необходима поддержка распознавания речи в браузере и разрешение микрофона.

## Проверка

Node.js 22 или новее:

```powershell
node verify.cjs
node prepare-pages.cjs
```

Если локальная политика Windows блокирует запуск файла Node.js по пути, команды можно выполнить через стандартный ввод:

```powershell
Get-Content -Raw verify.cjs | node
Get-Content -Raw prepare-pages.cjs | node
```

Готовая публикация находится в `dist/`. Скрипт копирует только HTML, требования и RFC. Локальные снимки экрана и экспорты данных в публикацию не включаются.

## GitHub Pages

1. Разместите проект в репозитории GitHub.
2. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Отправьте изменения в основную ветку (`main` или `master`).
4. Дождитесь завершения workflow **Deploy GitHub Pages** во вкладке **Actions**.
5. Откройте ссылку из deployment `github-pages`.

Workflow проверяет приложение, готовит статические файлы и публикует их. Последующие изменения основной ветки публикуются автоматически.

Основано на [официальном workflow GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Данные

Пользовательские записи хранятся в localStorage текущего браузера, не отправляются на GitHub и не синхронизируются между устройствами. При смене адреса с localhost на Pages браузер использует отдельное хранилище. Существующие записи останутся на прежнем адресе; полный импорт данных в приложении пока не реализован. Перед переносом можно сделать экспорт JSON для резервной копии.
